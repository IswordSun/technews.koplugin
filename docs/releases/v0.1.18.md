## 本版修复：诊断功能在部分设备上显示「无结果」

v0.1.17 的「网络诊断」在部分设备（如 Boox Nova3）上只显示「无结果」。原因是**子进程里不该调用 `Trapper:info`**：它会 `coroutine.yield()`，而子进程没有调度器来恢复协程，任务就卡住、父进程只能拿到空结果。KOReader 自己的子进程任务（如 wikipedia 的图片抓取）同样只返回字符串、不发送进度。

修法：

- 子进程任务内**不再调用任何 UI 函数**，只做探测并返回一段文本
- 整个探测过程包在 `pcall` 里：任何异常都会以**文本形式**回到屏幕上（而不是静默变成「无结果」）
- **兜底**：若子进程仍未返回结果（某些平台 fork/管道受限），自动改在**主进程**里直接探测（只测前两个目标，避免长时间无响应），并在标题下注明「已改为主进程直接探测」

## 本版仍包含

- **设置 → 网络诊断（分阶段）**：DNS → TCP → TLS → HTTP → gzip 自检，逐层显示耗时与错误原文，末尾附一个**纯 HTTP 对照目标**（用于区分「HTTPS 有问题」与「整机没网」）
- **设置 → 最近错误（诊断）**：插件最近的失败记录（40 条）直接显示在屏幕上
- gzip 三层保险、图片阶段止损（与 v0.1.16 相同）

测试：**17 个 spec / 739 项断言**全绿，`luacheck` 零告警。
