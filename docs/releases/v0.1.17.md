## 本版是诊断版：把"抓不到源"变成屏幕上的答案

### 背景

一台定制 Android 设备（Boox Nova3）上出现「除纯 HTTP 源外，所有 HTTPS 源都抓不到」——而同版本的 Kindle 完全正常。这类问题卡在 DNS / TCP / TLS / HTTP / 解压中的哪一层，**在设备上既没有 adb 也没有日志可看**，只能靠猜。

本版把诊断做进插件：**结果直接显示在设备屏幕上**，不需要 USB、adb 或 root。

### 新增

- **设置 → 网络诊断（分阶段）**：对已订阅源的入口逐层探测并显示每一步的耗时或错误原文：
  **DNS → TCP → TLS → HTTP → gzip 自检**，最后给出结论（例如「TLS 握手失败（能连上，但加密层建不起来）」）。
  为便于对照，末尾固定加一个**纯 HTTP 目标**（数字尾巴），用来区分「HTTPS 有问题」与「整机没网」。
  探测跑在**子进程**里：万一卡在 DNS 解析，界面依然可点，取消会直接杀掉它——"卡在 DNS"本身就是结论。
- **设置 → 最近错误（诊断）**：把插件自己记录的失败原因（最近 40 条）显示在屏幕上，不用再去翻 `crash.log`。
- 新增 `spec/diag_spec.lua`（25 项）：DNS/TCP/TLS 失败即止、结论指向正确的层、`http://` 不跑 TLS 阶段、渲染可读。

### 其它

- gzip 三层保险（探测 / 运行期熔断 / 即时明文重取）与图片阶段止损，与 v0.1.16 相同
- 测试：**17 个 spec / 739 项断言**全绿，`luacheck` 零告警

### 如果你正遇到"抓不到源"

1. 设置 → 网络诊断（分阶段），把屏幕结果拍下或抄下来
2. 设置 → 最近错误（诊断），同样看一眼
3. 把这两屏内容发我即可定位
